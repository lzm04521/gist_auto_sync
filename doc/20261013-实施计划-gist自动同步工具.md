# Gist Auto Sync V0.1 MVP 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 构建可在 Windows 安装运行的 Tauri 2 桌面应用：本地文件与 GitHub Gist / Opengist 的指定 gist 文件双向自动同步，冲突人工解决。

**Architecture:** React/TS/AntD 前端 ⇄ Tauri IPC ⇄ Rust 核心（provider 抽象层 [GitHub/Opengist REST] + 同步引擎 [watcher 防抖上传 / poller 轮询下载 / 三方比较] + config.json/快照/keyring 存储）。

**Tech Stack:** Tauri 2.x、Rust（tokio/reqwest/notify/serde/keyring/sha2/tracing/thiserror/wiremock/async-trait/tempfile）、React 18 + TypeScript 5 + Vite + Ant Design 5 + react-i18next + react-router-dom(HashRouter) + Vitest + @testing-library/react、diff。

**Spec:** `doc/20261013-设计文档-gist自动同步工具.md`（本计划依据 spec 第 10 节 V0.1 范围实现；执行者须同时阅读 spec）

## Global Constraints

- 平台 Windows 10+；仅 Tauri 2.x；Node ≥18 + pnpm；Rust stable。
- 所有 IPC DTO 字段 camelCase（Rust 侧 `#[serde(rename_all = "camelCase")]`），前端 `src/types.ts` 与之镜像。
- token 只经 Windows 凭据管理器（keyring service=`gistsync`）；config.json、快照、日志、错误消息中永不出现 token 明文；日志层提供 `redact()` 兜底。
- 本地文件按 UTF-8 文本处理；映射保存时校验，非 UTF-8 拒绝（spec §6.5）。
- 内容比较前规范化行尾（CRLF→LF）；下载写盘保留远端原始字节（spec §6.5）。
- `update_file` 的 PATCH 请求体只含目标文件一个 key，不得触碰 gist 其他文件（spec §5.5）。
- 三方比较：双方都 ≠ 快照 → 一律 Conflict（方向开关不豁免冲突，spec §6）；方向开关只决定 Upload/Download 是否自动执行。
- 默认值：debounceSeconds=3、pollIntervalMinutes=5、autoStart=true、logLevel="info"、language="zh-CN"；重试上限 5 分钟（spec §5.3/§6.6）。
- UI 全部文案走 i18n（zh-CN/en 键集合一致，有测试）；每任务一 commit，conventional commits。

## Review Focus

1. **CRLF/LF 假冲突**：Windows 编辑器保存 CRLF、远端 LF，若直接比对会永久"双方都变了"。→ Task 8 `normalize` 与 `decide` 分支测试（同内容异行尾 → Noop）。
2. **自写回路**：下载写盘触发 watcher → 又上传。→ Task 7 `SelfWriteGuard` 测试 + Task 10 引擎场景测试（下载后注入 LocalSettled → Noop）。
3. **误伤 gist 其他文件**：PATCH body 带多余 key 会改名/删除别的文件。→ Task 5/6 wiremock 断言 body 恰为 `{"files":{"<目标文件名>":{"content":…}}}`。
4. **断网/限流**：同步失败不得崩溃或丢状态。→ Task 4 错误映射矩阵（429+Retry-After）、Task 10 Network→Error 状态与 `backoff_delay` 上限测试。
5. **token 泄漏**：→ Task 2 config 落盘内容断言无 token 字段、Task 13 `redact` 测试、Task 3 keyring roundtrip（config.json 只存 tokenRef）。

### Task 10: 同步引擎核心（engine.rs）

**Files:**
- Create: `src-tauri/src/sync/engine.rs`；Test: 内联（FakeProvider 实现 Task 4 trait + tempdir 本地文件）

**Interfaces:**
- Consumes: Task 2/3/4/7/8/9。
- Produces:
  - `enum Trigger { LocalSettled, Poll, ManualUpload, ManualDownload }`
  - `enum MappingStatus { Idle, Uploading, Downloading, Conflict, Error, Missing, Paused }`（Error 带 `String` 消息）
  - `struct SyncCtx { config: Arc<ConfigStore>, snapshots: Arc<SnapshotStore>, providers: ProviderCache, guard: Mutex<SelfWriteGuard>, sink: Box<dyn StatusSink> }`；`ProviderCache::get(&self, account_id) -> Result<Arc<dyn GistProvider>>`（token 经 secrets 加载，账号更新时失效）；`trait StatusSink { fn emit(&self, mapping_id, status, last_synced_at, message) }`
  - `async fn run_sync_cycle(ctx: &SyncCtx, mapping: Mapping, trigger: Trigger) -> MappingStatus`
  - `fn backoff_delay(attempt: u32) -> Duration`（1s·2^n，封顶 300s）
- 行为（spec §6）：读本地→guard 命中→Noop；取远端（get_gist）；`decide` 后：Upload=archive 旧远端→update_file→get_gist 回读→snapshot 以回读内容更新；Download=archive 旧本地→按远端原始字节写盘→guard 登记→snapshot 更新；Conflict/写入状态经 sink emit。ManualUpload/ManualDownload 语义：local（remote）有未同步变更即执行覆盖（archive 优先），无变更返回 Idle+消息——同时充当冲突解决入口。网络/ProviderError::Network/RateLimited→Error + 计入重试（attempt 计数在 ctx）。

- [ ] **Step 1: 失败测试**（FakeProvider 可设 gist 内容/故障；断言 API 调用序列）：
  1. 上传：改本地→PATCH 一次→snapshot=回读 hash→旧远端已 archive；
  2. 下载：FakeProvider 改远端→本地文件内容更新（字节原样）→guard 已登记→旧本地已 archive；
  3. 回路抑制：紧接 2 注入 `LocalSettled` → 无 API 调用、状态 Idle（Review Focus #2）;
  4. 冲突：双方都改→Conflict、零写操作；
  5. MissingRemote：远端 gist 无该文件名且 snapshot 存在→Missing、零写操作；
  6. 网络故障→Error；`backoff_delay(20)==Duration::from_secs(300)`；
  7. ManualUpload 覆盖语义：双方都变时 ManualUpload→PATCH 执行、Conflict 清除；
  8. 首次映射：内容相等→SeedSnapshot（无写操作）；不等→Conflict。
- [ ] **Step 2: 确认失败** → **Step 3: 实现** → **Step 4: `cargo test engine` 通过**
- [ ] **Step 5: Commit** `feat(sync): sync engine core with fake-provider scenario tests`
