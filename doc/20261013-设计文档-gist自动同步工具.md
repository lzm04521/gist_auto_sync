# Gist Auto Sync 设计文档

- 日期：2026-10-13
- 状态：已与需求方逐节确认
- 仓库：`gist_auto_sync`（全新仓库，从零开始）
- 应用名（暂定）：Gist Auto Sync

## 1. 背景与目标

做一个开源的 Windows 桌面常驻工具，把本地指定的"gist 文件"与远端 gist 服务保持自动同步。首期支持两种 provider：

- **GitHub Gist**（REST API v3，`https://api.github.com`）
- **Opengist**（自托管实例，REST API，实例地址可配置）

核心场景：多机/异地同步片段文件——本地改了自动推上去，远端变了拉下来；双向都有变更时暂停并提示人工选择，绝不静默丢内容。

### 成功标准

1. 本地文件保存后 x 秒（可配置）自动上传到对应 gist 的对应文件，不影响 gist 内其他文件。
2. 远端 gist 变更后在轮询周期内自动下载覆盖本地（本地无未上传修改时）。
3. 双向同改时进入冲突状态，UI 人工三选一解决，无数据静默丢失。
4. token 等敏感信息不落盘明文（Windows 凭据管理器）、不入日志。
5. 开箱即用：安装包、开机自启、托盘常驻、中英文界面。

### 非目标（本期不做）

- 非 Windows 平台（架构上 Tauri 天然可移植，但不投入测试）
- 文件夹 ↔ gist 整体映射（映射粒度已定为单文件，见 2.1）
- 二进制文件同步（V0.1 仅文本文件；gist API 对内容本身按文本处理）
- 系统代理之外的网络特殊配置

## 2. 关键决策（已与需求方确认）

| 决策点 | 结论 |
|---|---|
| 映射粒度 | **文件 ↔ gist 内文件**（按文件名对应；同一 gist 可映射多个本地文件；未映射的其他文件一律不动） |
| "版本管理"范围 | 三项全要，分期实现：应用自身更新（V0.3）、同步内容历史/回滚（V0.2，快照数据 V0.1 开始积累）、gist 自带历史浏览（V0.2） |
| UI 技术栈 | **Tauri 2**（Rust 后端 + Web 前端） |
| 前端框架 | **React 18 + TypeScript + Vite**，组件库 Ant Design |
| 冲突策略 | **暂停并提示人工选择**（本地覆盖远端 / 远端覆盖本地 / 看 diff 再选） |
| 同步引擎 | **REST API 抽象层**（方案 A）：Rust trait `GistProvider`，GitHub / Opengist 各一实现，统一内部模型。不用 git 镜像仓库做同步 |

## 3. Provider 能力调研结论（证据链）

### 3.1 Opengist（当前 v1.15.2）

来源：仓库 https://github.com/thomiceli/opengist ，文档站 https://opengist.io/docs/api （2026-10-13 抓取）。

- REST API 完整可用。基础路径 `{instance}/api/`，数据格式 JSON。
- 认证：Personal Access Token（Settings → Access Tokens 创建，`og_` 开头，仅创建时显示一次），请求头 `Authorization: Bearer og_xxx`。
- Scope：`gist:read`、`gist:write`、`user:read`、`user:write`。
- 端点（覆盖本项目所需全部能力）：
  - `GET /gists` 列当前用户 gists，支持 `page`/`per_page`（默认 30、最大 100）/`since`（RFC3339 增量过滤）
  - `GET /gists/{id}`、`POST /gists`、**更新 gist**、`DELETE /gists/{id}`
  - `GET /gists/{id}/commits`（历史）、指定 revision 取 gist、raw 文件
  - `GET /users/me`（认证用户）
  - 完整 OpenAPI 3.1 规范可从实例 `GET /api/openapi.yaml` 获取（实现时以此为准做适配）
- 更新请求体 `GistUpdateRequest`：`files` 为 `map<string, GistUpdateFileInput | null>`，以**当前文件名**为键；`GistUpdateFileInput { content: string（新文件时必填）, filename: string（重命名） }`；`null` 值或两字段皆空 = 删除该文件。
- 实例可通过 `api.enabled: false` / `OG_API_ENABLED=false` 禁用 API（禁用时返回 403）——UI 的"测试连接"需要能把这个错误报告清楚。

### 3.2 GitHub Gist（REST API v3，稳定多年）

来源：GitHub REST API 文档（公共知识，实现时以官方文档为准）。

- 认证：PAT。推荐 classic token 勾选 `gist` scope；fine-grained token 若账号可用 "Gists" 权限也可。请求头 `Authorization: Bearer <token>`。
- 端点：`GET /gists`（列表，`per_page=100` 分页，`since` 过滤）、`GET /gists/{id}`、`POST /gists`、`PATCH /gists/{id}`、`GET /gists/{id}/commits`、`GET /gists/{id}/{sha}`（指定版本）。
- `PATCH /gists/{id}` 请求体 `files` 格式与 Opengist 几乎一致：`{ "文件名": { "content": "..." } }`，`null` 删除——**两边共享同一内部模型，适配层薄**。
- 支持条件请求（ETag / If-None-Match → 304）用于低成本轮询。
- 限流 5000 次/小时（认证后）；403/429 时读 `Retry-After` / `X-RateLimit-Reset`。

## 4. 总体架构

```
┌─ 前端 React 18 + TS + Vite + Ant Design（WebView2）
│     仪表盘 / 账号页 / 映射编辑 / 全局设置 / 历史页(V0.2) / 冲突解决弹窗
│    ⇅ Tauri IPC（invoke 命令 + event 推送状态）
├─ Rust 核心（Tauri 2）
│   ├─ provider 层：trait GistProvider + GithubProvider + OpengistProvider
│   │     （reqwest；统一内部模型 GistSummary / GistDetail / GistFile / GistCommit）
│   ├─ sync 引擎：
│   │   ├─ watcher（notify 监听映射文件父目录 → 防抖 → 上传队列）
│   │   ├─ poller（周期轮询远端变更 → 下载）
│   │   ├─ 每映射状态机（Idle/Syncing/Conflict/Error/Missing/Paused）
│   │   └─ 三方比较（local / snapshot / remote）判定上传|下载|冲突|忽略
│   ├─ 存储：config.json（账号/映射/全局设置）+ snapshots/（快照+历史）+ keyring（token）
│   └─ 插件：tray（托盘）、autostart、single-instance、updater（V0.3）、dialog
└─ 分发：GitHub Releases，NSIS 安装包
```

关键 crate：`tokio`（异步运行时）、`reqwest`（HTTP）、`notify`（FS 监听）、`serde`/`serde_json`、`keyring`（Windows 凭据管理器）、`sha2`（内容 hash）、`chrono`（时间处理）、`uuid`（ID 生成）、`tracing` + `tracing-appender`（滚动日志）、`thiserror`（错误分类）、`wiremock`（provider 单测）。

## 5. 数据模型与存储

### 5.1 Account（账号）

```json
{
  "id": "<uuid>",
  "name": "显示名",
  "provider": "github | opengist",
  "baseUrl": "github 固定 https://api.github.com；opengist 为实例根地址（如 https://gist.example.com）",
  "tokenRef": "gistsync:account:<id>"
}
```

- token 明文只存 Windows 凭据管理器（keyring crate），`tokenRef` 是凭据条目引用；配置文件、日志、快照中永不出现 token。
- 支持同类型多账号（例如两个 GitHub 账号、两个 Opengist 实例）。

### 5.2 Mapping（同步映射）

```json
{
  "id": "<uuid>",
  "localPath": "本地文件绝对路径",
  "accountId": "…",
  "gistId": "…",
  "gistFilename": "gist 内文件名，默认=本地文件名，可改",
  "uploadEnabled": true,
  "downloadEnabled": true,
  "enabled": true
}
```

约束：同一 `(accountId, gistId, gistFilename)` 组合唯一；`localPath` 唯一（同一本地文件不允许两条映射）。

### 5.3 GlobalSettings（全局设置）

```json
{
  "debounceSeconds": 3,
  "pollIntervalMinutes": 5,
  "autoStart": true,
  "logLevel": "info",
  "language": "zh-CN | en"
}
```

### 5.4 快照与历史（每映射一个目录 `snapshots/<mappingId>/`）

- `state.json`：`lastSyncedHash`（SHA-256 of 内容）、`lastSyncedAt`、`lastDirection`、`remoteUpdatedAt`。
- 历史文件：每次同步覆盖前，把**被覆盖一方**的旧内容存为 `<timestamp>-local.<ext>` / `<timestamp>-remote.<ext>`。这是 V0.2"内容历史/回滚"的数据源，V0.1 即开始积累。
- 历史文件数量上限与清理策略（如每映射保留最近 100 份）在 V0.2 实现 UI 时一并定；V0.1 先只写不清。

### 5.5 GistProvider trait（内部统一接口）

```rust
// Tauri 2 要求 Rust ≥ 1.77.2，原生 async fn in trait（稳定于 Rust 1.75）可直接使用，无需 async-trait crate
pub trait GistProvider: Send + Sync {
    async fn verify_token(&self) -> Result<UserInfo>;                 // "测试连接"
    async fn list_gists(&self, since: Option<DateTime<Utc>>) -> Result<Vec<GistSummary>>;
    async fn get_gist(&self, gist_id: &str) -> Result<GistDetail>;    // 含 files: HashMap<name, GistFile>
    async fn update_file(&self, gist_id: &str, filename: &str, content: &str) -> Result<GistDetail>;
    async fn list_commits(&self, gist_id: &str) -> Result<Vec<GistCommit>>;      // V0.2
    async fn get_file_at_revision(&self, gist_id: &str, rev: &str, filename: &str) -> Result<String>;  // V0.2
}
```

- 两实现各自把响应 JSON 转成统一模型；分页循环拉全量（per_page=100）；GitHub 条件请求（ETag）在实现内消化。
- 一个 gist 内多文件：`get_gist` 返回全部文件，引擎按 `gistFilename` 取目标文件计算远端 hash；`update_file` 的 PATCH 只带目标文件一个 key，**不动其他文件**。

## 6. 同步引擎行为

### 6.1 上传（本地 → 远端）

1. `notify` 监听所有启用映射文件的**父目录**（捕获改写、rename、删除事件）。
2. 事件进入防抖窗口：全局 `debounceSeconds`（默认 3 秒），**滑动重置**——窗口期内再次变动则重新计时，只处理最终状态。
3. 到期读文件、算 SHA-256：
   - `== snapshot.lastSyncedHash` → 忽略（仅触碰未改内容）；
   - 命中**自写抑制表**（引擎下载写盘时登记的 hash+mtime）→ 忽略，防止"下载→触发上传"回路；
   - 本地文件被删除 → 状态置 Missing（见 6.3），不自动删远端。
4. 与远端当前内容比对（`get_gist` 后取目标文件 hash）：
   - 远端 `==` 快照 → 直接 `update_file` PATCH；成功后更新快照，把旧远端内容写入历史；
   - 远端 `≠` 快照 且 本地 `≠` 快照 → **冲突**（见 6.4）。
5. 仅 `uploadEnabled && enabled` 的映射参与。

### 6.2 下载（远端 → 本地）

1. poller 每 `pollIntervalMinutes`（默认 5 分钟）运行：先列表粗筛（GitHub：`updated_at` 变化或 ETag 304 判断；Opengist：列表 `since` 参数），仅命中变动的 gist 再 `get_gist` 取内容，控制请求量。
2. 远端目标文件 hash：
   - `==` 快照 → 无变化；
   - `≠` 快照 且 本地 `==` 快照 → 写本地文件（写前把本地旧内容存历史；写后登记自写抑制表）；
   - `≠` 快照 且 本地 `≠` 快照 → **冲突**。
3. 仅 `downloadEnabled && enabled` 的映射参与。
4. 支持手动"立即下载"（仪表盘按钮），走同一判定逻辑。

### 6.3 Missing 状态

- 远端 gist 里找不到 `gistFilename`（被改名/删除），或本地文件被删除/路径失效 → 映射置 Missing，UI 提示。
- 人工二选一：改映射的 `gistFilename`（跟随远端改名）或在对应侧重建文件（远端重建=PATCH 新增该文件；本地重建=从远端下载）。**绝不自动删除任何一侧。**

### 6.4 冲突处理

- 判定即冲突的映射**暂停自动同步**（状态 Conflict），弹 UI 提示。
- 人工三选一：用本地覆盖远端 / 用远端覆盖本地 / 查看 diff 后再选（V0.1 为简单文本双栏对比）。
- 任一选择执行后，以选中方的内容重置快照，映射恢复自动同步。
- Conflict 状态持久化，重启后保留。

### 6.5 内容与 hash 基准（消除行尾差异误报）

- 快照基准内容一律以**远端回读内容**为准：上传 PATCH 成功后 `get_gist` 回读目标文件，用回读内容更新快照 hash（同时校验写入成功）。不以"本地发送了什么"为准。
- 本地参与比较的内容做**行尾规范化**（CRLF → LF）后再算 hash 与比对，避免 Windows 编辑器 CRLF 与 gist 存储 LF 造成永久"双方都变了"的假冲突；下载写盘时保留远端原始字节（不做反向转换）。
- 编码约定：V0.1 按 UTF-8 处理本地文件；非 UTF-8 文件在映射保存时即校验并提示不支持。

### 6.6 状态机与重试

- 每映射独立状态：`Idle / Syncing(↑|↓) / Conflict / Error / Missing / Paused`。
- 网络类失败：指数退避重试（1s/2s/4s…上限 5 分钟），恢复后自动续跑。
- GitHub 429/限流 403：按 `Retry-After` / `X-RateLimit-Reset` 暂停该账号的轮询与重试。
- 认证失败（401）：账号标"失效"，UI 提醒重新填 token；不影响其他账号。
- 状态与最后同步时间持久化，UI 实时展示（Tauri event 推送）。

## 7. UI 设计（前端页面）

托盘常驻；关闭窗口 = 最小化到托盘；退出走托盘菜单；单实例（再次启动唤起主窗口）。

1. **仪表盘（首页）**：映射列表（本地文件名 / 账号 / gist 链接 / 方向开关 / 状态徽标 / 最后同步时间 / 立即上传·立即下载·暂停按钮）；冲突处理入口；全局暂停开关。
2. **账号页**：账号列表（类型徽标 GitHub / Opengist、实例地址）；新增向导——选类型 → GitHub 填 PAT（附创建指引链接）；Opengist 填实例 URL + PAT → "测试连接"（`verify_token`，含 API 被禁用 403 的明确报错）；编辑、删除（有映射引用时阻止或要求确认级联）。
3. **映射编辑**：文件选择对话框（或手填绝对路径）→ 选账号 → gist 下拉（`list_gists` 拉取，显示描述 + 更新时间，支持搜索过滤；也可手填 gist id）→ gist 内文件名（默认本地文件名，可改）→ 上传/下载开关。
4. **全局设置**：防抖秒数、轮询间隔分钟、开机自启（联动 autostart 插件）、日志级别、打开日志目录、界面语言（中/英）。i18n 框架（如 i18next）V0.1 即搭建。
5. **历史页（V0.2）**：本地快照历史 + gist commits 历史，查看 / 对比 / 回滚到任意版本。
6. **冲突解决弹窗**：三选一 + diff 双栏（V0.1 简单文本对比）。

## 8. 错误处理与日志

- provider 错误统一分类：`Network / Auth(401) / Forbidden(403) / RateLimited(429/403+头) / NotFound(404) / ApiDisabled(Opengist 403) / Unknown`，映射到 UI 可读文案与恢复动作。
- 所有同步动作结果落日志：`tracing` → 按天滚动文件（app log dir），UI"打开日志目录"一键直达。
- 敏感信息红线：token、Authorization 头永不写日志、永不进错误上报文案。

## 9. 测试与验证策略

- **Rust 单元测试**：
  - provider 适配层：`wiremock` 模拟两种 API（列表分页、`since`、PATCH 请求体断言、401/403/404/429 错误映射、Opengist `files` map 与 GitHub 格式的双向转换）。
  - 同步引擎：三方比较全分支（两边都没变/仅本地/仅远端/都变→冲突）；防抖滑动窗口（tokio 时间 mock）；自写抑制表命中。
- **前端测试**：Vitest + Testing Library（账号类型切换的表单字段变化、映射表单校验、gist 下拉数据装配）。
- **集成测试（env-gated）**：真实 GitHub gist（专用测试账号 token，环境变量注入才启用，默认跳过），覆盖 create→update→verify 闭环。
- **手工验收清单**（Release 前）：
  1. 本地改动 → 防抖后远端变化，gist 其他文件不受影响；
  2. 远端改动 → 轮询周期内本地更新（可"立即下载"加速验证）；
  3. 双向同改 → 冲突提示 → 两种解决路径各自正确恢复；
  4. 断网保存 → 恢复网络后自动补传；限流提示正确；
  5. 重启应用 → 状态/冲突保留；自启动生效；
  6. token 在磁盘配置、日志、快照中 grep 不到明文。
